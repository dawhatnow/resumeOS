# M4 — Application history (as built)

**Status:** done  
**Job:** every resume you export is kept as a folder you can list, reopen, re-export, and track. The PDF still goes to the Desktop.

## Commands

```bash
resume ls                        # newest first: #, role · company, fit, status, date
resume open 1                    # back into review for that job (# from ls, or part of the id)
resume open shyftlabs --rewrite  # …and AI-tailor when review opens
resume export 1                  # re-compile that exact resume onto the Desktop
resume status 1 applied          # exported | applied | interview | offer | rejected | withdrawn
```

## Folder per application

```
~/.resume/applications/2026-09-26_shyftlabs_associate_ai_engineer/
  job.yaml      url, source, company, title, raw JD (reopen never refetches)
  plan.yaml     reviewed picks, your edits, AI rewrites, style
  resume.yaml   exactly what the template rendered + what was left out to fit
  diff.yaml     vs the warehouse: included / not included items, dropped, edited, AI-rewritten
  resume.pdf
  meta.yaml     id, company, title, coverage, status, created/updated, Desktop path
```

Id: `YYYY-MM-DD_company_role`, `-2`, `-3`… on a clash. Nothing here is written into `profile.yaml`.

## How it behaves

- **Save:** after the PDF is written to the Desktop, the folder is written too; the finish panel shows `📁 saved as <id>`. Pasted/file JDs get their company from a "Company — Location" style line near the top; if there isn't one, you're asked once.
- **Open:** reloads the saved job and plan, re-reads the job against **today's** warehouse (new scores, coverage), and goes straight to review with your old picks, edits, rewrites and style. Items or bullets deleted from the warehouse since are skipped with a note. Approving updates the same folder and overwrites that application's own Desktop PDF (not a `-2` copy).
- **Export:** compiles the saved `resume.yaml` data again, so it's the same content even if the warehouse changed since.
- **Status** is kept across reopen/re-export.

## Files

| File | Function |
|---|---|
| `app/applications.py` | `ApplicationStore`: ids, save/update, list, `require` (id / # / unique part), load posting/plan/render data, status |
| `app/planning/planner.py` | `evaluate()` — scores and coverage for a saved selection |
| `app/render.py` | `compile_data()` — re-compile saved template data |
| `app/cli.py` | `ls`, `open`, `export`, `status`; save on export |

## Tests

`tests/unit/test_applications.py` — two jobs same day → distinct ids, folder contents + round trip, reopen against a changed warehouse, update in place keeps created/status, lookup by # / part / ambiguity, bad status, company detection. The end-to-end run (two jobs, reopen the first and drop an item, re-export, set status) was done through the real CLI.
