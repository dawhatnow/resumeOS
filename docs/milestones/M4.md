# M4 — Application history (plan)

**Status:** not started  
**Job:** after export, keep a named record you can reopen. PDF still goes to Desktop.

## What to build

```
~/.resume/applications/2026-09-26_stripe_backend/
  job.yaml       url/paste, company, title, raw JD
  plan.yaml      selected / excluded IDs + reasons
  resume.yaml    approved lines + source_id
  diff.yaml      vs warehouse: included / dropped
  resume.pdf
  meta.yaml      id, timestamps, desktop path, status
```

Commands: `resume ls`, `resume open <id>`, `resume export <id>`.

## New files

| File | Function |
|---|---|
| `app/applications.py` | save / load / list / id slug |
| `app/models.py` | `Generation` (job + plan + resume + pdf_path) |

Do not store this inside `profile.yaml`. Warehouse stays inventory; applications are compiles.

## Libraries

| Lib | Use |
|---|---|

| **Typer + Rich** | `ls` table, reopen review |
| stdlib `pathlib`, `datetime` | folders and ids |

No database. No hosted link.

## How to code it

1. On approve in M3, write the folder **and** the Desktop PDF.
2. Id: `YYYY-MM-DD_company_role`, suffix `-2` on clash.
3. `ls`: newest first, id / company / title / status.
4. `open`: reload review from `plan.yaml` + warehouse (don’t re-fetch unless asked).
5. `export`: compile again to Desktop from saved `resume.yaml`.

## Done when

Two jobs in one day; reopen the first; re-export.
