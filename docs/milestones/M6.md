# M6 — AI bullet rewrite (as built)

**Status:** done (built before M4/M5)  
**Job:** tailor the wording of the bullets you kept to the job's keywords, so an ATS matches them — without adding a single fact. Optional; off unless you ask for it.

## Use it

```bash
resume new ./jd.txt --rewrite     # rewrite all kept bullets as soon as review opens
```

Or in the review screen:

| Type | Does |
|---|---|
| `rewrite` | all bullets on the resume (your own ✎ edits are left alone) |
| `rewrite exp.2` / `rewrite exp.2.3` | one job/project, or one bullet — handy with a slow local model |
| `reset exp.2.3` / `reset all` | back to the original wording |

Rewrites show as **✦** with the old and new text. You approve the plan as usual; nothing is written to `profile.yaml`.

## Pick a model — `~/.resume/config.toml`

No config = Ollama with `phi3.5`. Every provider below speaks the OpenAI chat format, so one class (`OpenAICompatibleProvider`) handles all of them.

```toml
[llm]
provider = "ollama"          # local, private, free. Needs `ollama serve` + `ollama pull <model>`
model = "phi3.5"
```

```toml
[llm]
provider = "groq"            # free tier, fast. export GROQ_API_KEY=...
model = "llama-3.3-70b-versatile"
```

```toml
[llm]
provider = "gemini"          # free tier via Google AI Studio. export GEMINI_API_KEY=...
model = "gemini-2.5-flash"
```

Also `openrouter` (`OPENROUTER_API_KEY`), `none` (turn it off), or any OpenAI-compatible server with `base_url = "..."` and `api_key_env = "..."`. Optional `timeout = 300`. Env overrides: `RESUME_LLM_PROVIDER`, `RESUME_LLM_MODEL`.

Keys come only from environment variables, never the config file. Cloud providers see the bullets you send them (and their free tiers may train on them); Ollama never leaves your machine. Default model names drift — if one 404s, set `model`.

**On this dev machine** (WSL, 6 GB RAM, no GPU): `phi3.5` ≈ 25 s per bullet, `llama3.1` ≈ 65 s. A whole resume locally takes minutes; `rewrite exp.2` one item at a time, or use a cloud provider for speed.

## How it works

```
kept bullet ids → BulletWriter (app/ai/writer.py)
  one batched call: {job title, job keywords, per bullet: original, may_use, max_chars}
  → TruthGuard.check_rewrite on every answer
  → failures: ONE retry with {previous_attempt, problems}
  → still failing: keep the original
  → accepted texts become plan.edits (+ plan.rewritten)
```

- `may_use` = the job's terms that **this bullet's own job/project** backs up. The model is told it may only name those plus what the original already says.
- At most 2 calls per `rewrite`.

## Truth guard for AI rewrites (`TruthGuard.check_rewrite`)

Everything `check_bullet` enforces (M3: no new numbers, no tech the item doesn't back, length ≤ 130% / 260 chars), **plus nothing valuable may be lost**:

- every number in the original must still be there (a first live test with `phi3.5` quietly deleted `RMSE 5.25`, `258/340 ms`, `7.5 rps` — now rejected);
- every job keyword the original mentions must still be there.

Your own edits in review aren't held to the "no loss" rule — trimming is your call.

## Files

| File | Function |
|---|---|
| `app/ai/provider.py` | `load_provider()` from config/env; `OpenAICompatibleProvider`; `NullProvider`; `ProviderError` with user-facing messages (not running, bad key, unknown model, rate limit, timeout) |
| `app/ai/writer.py` | prompt, batching, JSON parsing (tolerates code fences), guard, retry, fallback |
| `app/guard.py` | `check_rewrite`, `allowed_terms`, `max_chars` |
| `app/review.py` | `rewrite` / `reset all` commands, ✦ marks |

## Tests

`tests/unit/test_ai_rewrite.py` — scripted fake provider: accepted in one call, invented facts → retry → original kept, retry fixes it, no-loss rule, unchanged/missing answers, JSON parsing, review integration + `reset all`, your edits untouched, config/env/key loading, unreachable server message.
