# M1 — Warehouse CLI (as built)

**Status:** done  
**Job:** turn resume PDFs (and typed extras) into one local warehouse.

## Commands

```bash
pipx install resumeos             # user install — no GitHub clone (M7 / git URL until then)
resume init                       # start: import one or more PDFs
resume                            # status + next steps
resume import --merge other.pdf   # add another resume later
resume add experience | project | bullet
resume show
```

Saved at `~/.resume/profile.yaml` (or `$RESUME_HOME/profile.yaml`).

## Libraries

| Lib | Where | Why |
|---|---|---|
| **Typer** | `app/cli.py` | commands, `--merge`, `-y`, `pip` entry point `resume` |
| **Rich** | `app/term.py`, `app/cli_ui.py` | color: green Done, yellow Next, cyan IDs, red errors |
| **pdfplumber** | `PdfTextExtractor` | text with `x_tolerance=0.5` so styled/link spans keep spaces |
| **pypdf** | `LinkAnnotationExtractor` | clickable `/Annots` URIs (“LinkedIn” with no visible URL) |
| **PyYAML** | `ProfileStore` | dump/load dataclasses to `profile.yaml` |
| **pytest** | `tests/unit/` | import regressions, merge, CLI |

No httpx, no LLM, no Typst. Those belong to later milestones.

Python 3.11+ (`X | None`). Stdlib: `dataclasses`, `pathlib`, `re`, `os`.

## How it’s coded

```
PDF
  → PdfTextExtractor + LinkAnnotationExtractor
  → ProfileImporter (section parsers)
  → Profile
  → ProfileMerger? (only --merge)
  → ProfileStore → ~/.resume/profile.yaml
```

CLI is thin. Merge/add live in `app/warehouse.py`. Parsers live in `app/importing/`.

### Import (`ProfileImporter`)

1. Validate `.pdf` exists.
2. Extract text (`pdfplumber`) and link URIs (`pypdf`).
3. Split on headings (`SectionSplitter`).
4. Parse experience / projects / education / skills / contact.
5. Build vocabulary; tag bullets with terms they actually contain (longest first).
6. Keep unknown sections in `other_sections`.

**Wrapped bullets:** a non-bullet line is a new item only on a positive header (`Title @ Org Jan 2023 - Present`, or project + `§ Code Python, Redis`). Otherwise it folds onto the last bullet. That bug used to turn 4 jobs into 19.

**Skills:** category labels only at line start. Joining the whole section dropped “Golang” when it touched the next `Category:`.

### Merge (`ProfileMerger.merge`)

Same job = same title + org (case-insensitive, collapsed space).

- Hit: keep `exp.1`; union bullets; skip duplicate text; mint `exp.1.3` for new lines.
- Miss: append `exp.N` / `proj.N`.
- Skills, links, education details: union (first casing wins).
- Personal: fill blanks only. Existing summary wins.
- Rebuild vocabulary after.

`MergeReport` is what the CLI prints (`1 new jobs, 3 new bullets, 1 duplicates skipped`).

### Add

`add_experience` / `add_project` / `add_bullet` mint the next id and call `refresh_vocabulary`. Unknown `item_id` raises `ValueError`.

### CLI UX

Bare `resume` = warehouse status + **Next**. Every success prints **Done** then **Next**. Empty warehouse tells you to `resume import`.

IDs in Rich must be `\[exp.1]` so `[exp.1]` is not parsed as a markup tag.

### Speed

`ProfileImporter` (pdfplumber + pypdf) is imported **only inside** `_import_pdf`. `resume` / `show` / `add` stay ~0.4s. Import stays ~1s because it reads a PDF.

Tech-tag regexes compile once per vocabulary, not once per bullet.
