# M3 — Review + PDF (as built)

**Status:** done  
**Job:** after the match, review the picks in the terminal, then write a one-page PDF to the Desktop. Wording is the original bullets unless you edit one (edits are truth-checked). No LLM.

## Commands

```bash
resume new ./jd.txt            # match → "Review these picks and build the one-page PDF?"
resume new - --pdf             # paste, go straight to review
resume new <url> --no-pdf      # match only (M2 behaviour)
```

`resume init` session → `paste` asks the same question after the match.

## Flow

```
ResumePlan (M2)
  → PlanReviewer   toggle / edit / up / add / drop / approve   (app/review.py)
  → TruthGuard     on every edit                               (app/guard.py)
  → ResumeRenderer JSON → Typst → PDF, fit loop to one page    (app/render.py)
  → file name prompt → Desktop (never overwrites: name-2.pdf)
```

## Review commands

| Type | Does |
|---|---|
| Enter / `pdf` | approve and build |
| `exp.2.3` | toggle that bullet on/off |
| `edit exp.2.3` | rewrite a bullet; rejected with reasons if the guard fails |
| `reset exp.2.3` | undo an edit |
| `up exp.2.3` | move a bullet up |
| `add proj.3` / `drop exp.4` | add (top-scored bullets) or remove an item |
| `list`, `?`, `quit` | show all, help, cancel |

Edits live on the plan (`ResumePlan.edits`) and are never written back to `profile.yaml`.

## Truth guard (`app/guard.py`)

A rewritten bullet fails if it:

1. is for a bullet id that isn't in the warehouse, or is empty;
2. contains a number not in the source bullet (`10,000` = `10000`);
3. mentions tech not backed by **that bullet's own job/project** (its title, declared tech, or any of its bullets, plus implied terms like PostgreSQL → SQL). Tech you used elsewhere doesn't count: Redis from a project can't appear on a job that never used it;
4. is more than 30% longer than the source (max 260 chars).

The same guard will check M6 AI rewrites.

## Rendering (`app/render.py`, `app/templates/resume.typ`)

- **Typst via the `typst` pip package** (bundled compiler, no separate install). Fonts: Typst's embedded New Computer Modern with `ignore_system_fonts=True`, so output is identical on every machine.
- Data goes in as JSON through `sys.inputs`; strings are inserted as plain text, so `#`, `$`, `*`, `@`, `<` in bullets are never parsed as markup.
- Layout: one column, real text, standard headings (Education, Experience, Projects, Skills) — ATS-safe. Jobs in warehouse order, projects by relevance, skills the JD asks for first.
- Header links: only profile links (LinkedIn, GitHub user, personal domain); per-project repo links are skipped.
- Duplicate education entries from merged PDFs are collapsed (first wins).
- **Fit loop:** 10.5pt → 10pt → drop the lowest-scoring bullet (never an item's last one; only then the weakest item) → then try putting dropped bullets back, strongest first, if they now fit. What was left out is printed.
- Output: `RESUME_OUTPUT_DIR` if set, else the Windows Desktop under WSL (asks Windows, so OneDrive Desktop works), else `~/Desktop`, else the current folder.
